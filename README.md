
# Real Estate Market Analysis Using MySQL

## Project Overview

The **Real Estate Market Analysis** project uses MySQL to analyze property listings, customer purchases, agent performance, and city-wise sales revenue.

The project demonstrates practical SQL skills through database design, data analysis, subqueries, JOINs, aggregate functions, and views to extract meaningful business insights from real estate data.

**Note:** This project uses a synthetic dataset created for learning and portfolio purposes. It does not represent actual real estate market data.

## Project Objectives

- Analyze property prices across different cities and localities.
- Identify sold, available, and booked properties.
- Evaluate real estate agent sales performance.
- Analyze customer budgets and purchasing behavior.
- Calculate city-wise sales and revenue.
- Practice SQL queries using JOINs, subqueries, and views.

## Tools & Technologies

- **Database:** MySQL
- **Language:** SQL
- **Concepts:** Database Design, Primary Keys, Foreign Keys, Constraints, Aggregate Functions, GROUP BY, HAVING, JOINs, Subqueries, Views, CASE Statements

## Database Structure

The project contains six relational tables:

| Table Name | Description |
|---|---|
| `Property_Types` | Stores property categories and descriptions |
| `Locations` | Stores city, state, locality, and ZIP code |
| `Properties` | Stores property details, prices, sizes, and status |
| `Customers` | Stores customer information and budgets |
| `Agents` | Stores agent information, experience, and commission rates |
| `Transactions` | Stores property sales, selling prices, and payment modes |

## Table Relationships

- `Properties` references `Property_Types` through `Type_ID`.
- `Properties` references `Locations` through `Location_ID`.
- `Transactions` references `Properties` through `Property_ID`.
- `Transactions` references `Customers` through `Customer_ID`.
- `Transactions` references `Agents` through `Agent_ID`.

These relationships maintain data consistency and support analysis across multiple tables.
